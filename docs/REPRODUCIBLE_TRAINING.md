# Reproducible Iceberg training and evaluation

The official training path never reads a mutable table head during model fitting.
The dataset builder first resolves one snapshot ID for each required Iceberg table,
then reads both tables with Spark's `snapshot-id` option. The resulting dataset
identity is the SHA-256 of the schema version, the complete table-to-snapshot map,
the label/filter contract, and a semantic builder revision. Changing transformation
logic requires changing that revision so updated code cannot collide with a dataset
identifier produced by older logic.

## Automated run

Trigger the `ai_train_pipeline` Airflow DAG with `dataset_version=auto`. Leave both
snapshot parameters at `0` to resolve each current snapshot exactly once, or provide
both positive IDs to replay a previously recorded source state:

- `post_features_snapshot_id`
- `engagement_snapshots_snapshot_id`

Supplying only one ID is rejected. Explicit snapshot IDs are also rejected when an
existing `dataset_version` is selected, avoiding an ambiguous mix of two identities.

The equivalent Spark command is:

```bash
docker exec spark-master /opt/spark/bin/spark-submit \
  --master spark://spark-master:7077 \
  /opt/spark/jobs/maintenance/build_training_dataset.py \
  --dataset-version auto \
  --post-features-snapshot-id 123 \
  --engagement-snapshots-snapshot-id 456 \
  --manifest-output /opt/spark/balancing/ml/runs/paper-run.json
```

Omit the two explicit snapshot arguments only when the intent is to lock the current
table heads for a new run. The emitted manifest remains the authoritative record of
the IDs that were actually used.

## Provenance contract

An official manifest is accepted only when all of these checks pass:

- `dataset_version` matches the schema version and the first 20 hexadecimal
  characters of `dataset_fingerprint`;
- the fingerprint recomputed from the pinned snapshots and filters is identical;
- `source_tables_json` and `iceberg_snapshots_json` describe the same tables;
- every snapshot ID is a positive integer;
- the versioned Parquet path is relative, contained by the export root, and named
  after the dataset version;
- every training row carries exactly that dataset version.

Training embeds the validated lineage in the serialized model and writes a
`*.lineage.json` sidecar containing the model SHA-256. Evaluation writes
`ml/results/stage1_evaluation.json` with the same lineage and model digest. The
generated Markdown report prints the dataset version, full fingerprint, manifest
digest, and every table/snapshot pair above the performance figures.

## Reporting rule

Only figures generated by an official run may be used as reproducible paper results.
Each table or figure caption must cite at least the `dataset_version`; the accompanying
artifact bundle must retain the full `dataset_fingerprint`, `manifest_sha256`, and
`iceberg_snapshot_ids` from the evaluation JSON. Results without these fields are
historical, non-versioned measurements and must not be presented as reproducible
Iceberg results.
